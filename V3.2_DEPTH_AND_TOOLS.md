v3.2 — Depth mode + normal Gazebo tools

Fixes:
1. Depth mode now robustly accepts common Gazebo depth formats:
   R_FLOAT32 / FLOAT32, UINT16, and 8-bit fallback.
2. Depth frames are explicitly logged:
   first Gazebo DEPTH frame received from front_depth
3. Selected mode now logs its type:
   display -> front_depth (depth)
4. Depth visualization is always colorized with a visible `DEPTH` label.
5. Normal Gazebo GUI testing tools are retained from v3.1.
6. The working monitor geometry / SceneManager arrangement is unchanged.

Build:
cd ~/gz_sensor_monitor_ws
source /opt/ros/jazzy/setup.bash
rm -rf build install log
colcon build --symlink-install --packages-select gz_sensor_monitor
source install/setup.bash

Run:
export GZ_SIM_SYSTEM_PLUGIN_PATH=$HOME/gz_sensor_monitor_ws/install/gz_sensor_monitor/lib
export GZ_GUI_PLUGIN_PATH=$HOME/gz_sensor_monitor_ws/install/gz_sensor_monitor/lib

gz sim --force-version 8 -r -v 4   ~/gz_sensor_monitor_ws/install/gz_sensor_monitor/share/gz_sensor_monitor/worlds/sensor_monitor_demo.sdf

RGB:
ros2 topic pub --once /sensor_monitor/mode std_msgs/msg/String "{data: front_rgb}"

DEPTH:
ros2 topic pub --once /sensor_monitor/mode std_msgs/msg/String "{data: front_depth}"

RGB-D:
ros2 topic pub --once /sensor_monitor/mode std_msgs/msg/String "{data: front_rgbd}"

LIDAR:
ros2 topic pub --once /sensor_monitor/mode std_msgs/msg/String "{data: front_lidar}"

For depth, the runtime log should contain:
  [GzSensorMonitor] display -> front_depth (depth)
  [GzSensorMonitor] first Gazebo DEPTH frame received from front_depth
  [GzSensorMonitor GUI] first display frame received: 640x480 ...
